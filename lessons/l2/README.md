# L2. Типизированный интерфейс React

## Зачем эта тема

На L1 вы создали типы и функции данных. Теперь вы используете эти типы в React: props задают входы компонентов, проверка `kind` помогает показать обе формы задания, а небольшой state хранит выбор текущего задания. Вы продолжаете доменный слой A1 и добавляете интерфейс одного учебного модуля.

Перед началом откройте существующую папку `trainer/` и убедитесь, что в ней есть ваша версия A1. Подключите React и Vite к этому проекту, сохраните A1 и свои файлы, а поля конфигурации обновите по [гайду](docs/GUIDE.md). Не создавайте проект заново генератором и не теряйте накопленный код.

React и Vite подключаются к тому же проекту точными версиями, выбранными для курса:

```sh
npm install react@19.3.0 react-dom@19.3.0 --save-exact
npm install vite@6.4.3 @vitejs/plugin-react@4.3.4 @types/react@19.3.0 @types/react-dom@19.3.0 --save-dev --save-exact
```

Команды одинаковы в Linux и Windows PowerShell. После установки проверяйте исходники через `npm run dev`, а готовый результат — через `npm run build` и `npm run preview`; типы отдельно проверяет `npm run check`. Настройка `preview` приведена в гайде. До L6 команда `npm test` не обязательна: тестовый раннер и RTL появятся на отдельном этапе.

## Задание A2

Продолжите A1 в той же папке `trainer/`. Покажите один учебный модуль: его название, список заданий и карточку текущего задания. Используйте локальный типизированный набор из A1, не меняя смысл уже написанных типов и функций. Второй модуль из A1 остаётся данными для проверки функций; интерфейс выбора между модулями здесь не требуется.

### Обязательная структура

- компонент списка получает массив заданий и callback выбора через props;
- отдельный компонент одного задания получает один объект через props и показывает `prompt`, `topic` и необязательный `code`;
- для `single-choice` отображаются `options`, а для `short-text` — понятное сообщение о текстовом типе без поля ввода;
- заголовок показывает название модуля и количество заданий;
- родитель хранит строковый id выбранного задания в одном `useState` и передаёт необходимые данные дочерним компонентам;
- у элементов списка используется стабильный `task.id` в `key`, а не индекс массива.

Имена компонентов и внутреннюю структуру определите самостоятельно. Данные могут оставаться локальным типизированным модулем A1. Назначение вариантов модуля сервером на этом этапе не требуется.

### Сценарии проверки

1. При старте непустого модуля виден список и одно выбранное задание.
2. Нажатие на стандартную кнопку меняет карточку без перезагрузки.
3. Обе формы задания отображаются безопасно: варианты читаются только у `single-choice`.
4. Значение `code` показывается как текст и не исполняется.
5. Если модуль пуст или выбранный id отсутствует, виден нейтральный пустой экран, а не ошибка доступа к отсутствующему объекту.
6. В узком окне текст читается. Кнопки выбора задания доступны через Tab и срабатывают от Enter или пробела без дополнительного `tabIndex`.
7. Функции A1 по-прежнему проходят `npm run check` и демонстрацию.

### Границы

Кнопка выбора меняет только текущее задание. Не добавляйте поля ответов, `onChange` ответов, формы, API, сохранение, генерацию варианта, `useReducer` или сторонние библиотеки. Позже сервер будет назначать набор заданий конкретной попытке; на A2 достаточно локальных данных. Каталог нескольких модулей — возможное дополнительное задание после основной логики курса, в зачёт A2 не входит.

**Вопросы:** Кто владеет состоянием выбора? Как карточка получает данные? Почему `key` должен быть стабильным? Что происходит при отсутствии id? Как показать `code` безопасно?

## Проверка и сдача

Из `trainer/`, одинаково в Linux и Windows PowerShell. Во время разработки:

```sh
npm run dev
```

Перед сдачей отдельно проверьте типы и собранное приложение:

```sh
npm run check
npm run build
npm run preview
```

`preview` показывает файлы из `dist/`, созданные командой `build`; `dev` работает с исходниками. Остановите каждый сервер после ручной проверки. A2 сдаётся на P3; предыдущая работа A1 должна оставаться в той же ветке или в основании новой ветки.

## Критерии зачёта

- проект продолжает A1, а React и Vite добавлены в существующую папку;
- данные действительно проходят через props;
- список и карточка разделены по ответственности;
- `kind` сужается перед чтением полей конкретной формы;
- `useState` меняет выбранный id без дублирования всего объекта;
- `task.id` используется как стабильный `key`;
- отсутствующий id и `code` обрабатываются безопасно;
- `npm run check` и `npm run build` проходят.
