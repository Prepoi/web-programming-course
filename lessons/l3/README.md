# L3. Ответы, формы и прохождение попытки

## Что нужно сделать

В `trainer/` продолжите приложение из A2. Пользователь должен пройти локальную тренировочную попытку по учебному модулю:

- выбрать вариант у `single-choice`;
- ввести ответ у `short-text`;
- использовать controlled radio и textarea: отображаемые значения должны приходить из состояния React;
- переходить назад и вперёд без потери уже введённых ответов;
- видеть прогресс и список незаполненных заданий;
- вычислять прогресс и список незаполненных по текущим ответам, а не поддерживать их отдельными несвязанными копиями;
- пропускать задание, но получить предупреждение перед завершением;
- увидеть обзор ответов после локального завершения.

Это учебный локальный режим. Сервер, оценивание и `fetch` появятся позже. Не вычисляйте клиентскую оценку, не отправляйте ответы наружу и не используйте `localStorage` или `sessionStorage`.

## Ограничения контракта

Используйте `Task.id` как ключ ответа. Форматы ответов:

```ts
type Answer =
  | { taskId: string; kind: "single-choice"; optionId: string }
  | { taskId: string; kind: "short-text"; text: string };
```

Пробелы и пустая строка в `short-text` считаются незаполненным ответом. Текст из `Task.code` показывайте как текст, не исполняйте.

## Самостоятельная реализация

Порядок реализации, состав компонентов и внутреннее представление состояния выберите самостоятельно. Для ручной проверки используйте модуль из `course/data/training-set.json`.

## Сдача и критерии

A3 сдаётся до следующей собственной практики. На P4 проверяется именно эта работа, а P3 проверяет A2.

Зачётный сценарий: изменить ответ, пройти задания в другом порядке, вернуться к тексту, увидеть пересчитанный прогресс, завершить с пропуском и убедиться, что завершённую попытку нельзя редактировать без явного старта новой попытки. Если предупреждение отменено, ответы и возможность редактирования сохраняются. Новая попытка явно сбрасывает локальное состояние, но работает с тем же фиксированным модулем. Серверное назначение варианта появится позже.
