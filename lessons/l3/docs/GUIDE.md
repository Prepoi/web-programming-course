# Гайд L3: формы и состояние попытки

[Задание](../README.md) · [Гайд](GUIDE.md) · [Справка](CHEATSHEET.md) · [Интерактив](interactive.html) · [Слайды](slides-standalone/slides.html)

## Зачем это нужно

Форма тренажёра — это не набор независимых кнопок, а интерфейс прохождения модуля. Ответ должен переживать переходы между заданиями, а интерфейс должен в любой момент объяснять, сколько уже сделано и что осталось. Для этого ввод становится контролируемым: текущее значение хранится в состоянии React, а элемент формы получает его через `value` или `checked`.

Контролируемое поле получает текущее значение из состояния и сообщает об изменениях через событие. `render` — повторное описание интерфейса по текущим данным; оно не равно перезагрузке документа. Размонтирование — удаление экземпляра компонента из дерева React; его локальное состояние после этого больше не существует.

## Контролируемое поле

```tsx
function NameField() {
  const [name, setName] = useState("");

  return (
    <label>
      Имя
      <input
        value={name}
        onChange={(event) => setName(event.target.value)}
      />
    </label>
  );
}
```

Событие сообщает новое значение, а setter обновляет состояние. Не читайте значение только из DOM при переходе: тогда легко потерять его или рассинхронизировать обзор.

Это пример на отдельном поле, а не готовый фрагмент trainer. Для A3 сохраните тот же принцип для radio и textarea, но структуру компонентов и место хранения состояния выберите самостоятельно.

## Разные формы данных

В небольших моделях данных дискриминатор `kind` помогает TypeScript понять, какое поле доступно. Например, это может быть состояние уведомления, не связанное с trainer:

```tsx
type Notice =
  | { kind: "info"; text: string }
  | { kind: "error"; code: number };

function describe(notice: Notice) {
  return notice.kind === "info" ? notice.text : `Ошибка ${notice.code}`;
}
```

В A3 аналогичный принцип применяется к двум вариантам `Answer`, описанным в задании.

`Task.id` связывает ответ с заданием. Позиция задания на экране может измениться, поэтому она не должна быть идентичностью ответа. Способ хранения коллекции и границы компонентов для A3 выберите самостоятельно.

## Неизменяемое обновление

Не меняйте массив через `push` и не изменяйте объект состояния на месте: React может не увидеть ожидаемое новое значение. Для нового значения коллекции используют, например, такие операции:

```ts
const changed = items.map((item) =>
  item.id === targetId ? { ...item, selected: true } : item,
);
const withoutItem = items.filter((item) => item.id !== targetId);
const extended = [...items, nextItem];
```

Выберите подходящую операцию для своей модели и сохраните инвариант контракта: у одного задания не должно появляться несколько актуальных ответов.

## Подъём состояния

Если одни и те же данные нужны полю, навигации и обзору, их владелец должен быть общим для этих частей интерфейса. Поле отвечает за отображение и события, а состояние попытки должно жить достаточно долго, чтобы переход между заданиями его не стирал. Необязательные для других частей временные значения можно оставить локальными.

Для A3 определите владельцев самостоятельно и объясните, почему выбранное размещение переживает нужный переход.

## Производные значения

Прогресс и список незаполненных заданий — производные значения. Не храните их отдельными копиями, если их можно получить из ответов и набора заданий. Для текста полезна единая проверка:

```tsx
const isFilledText = (value: string) => value.trim().length > 0;
```

Для выбранного варианта проверяется наличие `optionId`. В своей реализации задайте один согласованный способ проверки ответа и используйте его для прогресса, списка пропусков и предупреждения перед завершением. Если хранить и исходные ответы, и `answeredCount`, они могут разойтись.

## Навигация

Текущее задание можно выбирать индексом или другой внутренней моделью, но значение должно оставаться в допустимых границах. Переход меняет отображаемую позицию, а не идентичность ответа и не должен очищать уже введённые данные. Переход к обзору не означает серверную отправку.

## Завершение

Перед завершением найдите пропущенные задания и покажите их идентификаторы или номера. Если пользователь отменяет предупреждение, попытка остаётся открытой, а ответы не меняются. После подтверждения состояние переходит в `submitted`, форма заменяется обзором или становится недоступной для редактирования. Новую попытку начинайте отдельным явным действием, которое сбрасывает состояние текущей локальной попытки.

В A3 нет API, серверной оценки, `fetch`, `localStorage` или `sessionStorage`. Перезагрузка страницы может начать локальную попытку заново; сохранение между загрузками относится к последующим этапам.

## Доступность и проверка

Связывайте `label` с полем, используйте настоящие `button`, `fieldset` и `legend`, а не кликабельные `div`. Проверьте клавиатурой: выбор радиокнопки, переход к следующему заданию, возврат и редактирование текста. Отдельно проверьте пустой и пробельный ответ.

## Небольшая самопроверка

- Можно ли открыть задание 3, ответить, перейти на 1 и вернуться на 3?
- Меняется ли прогресс после удаления текста до пробелов?
- Остаётся ли ответ в обзоре после завершения?
- Заблокировано ли редактирование до явного старта новой попытки?
