Состояние: память работающей системы

  • Программа помнит факты, от которых зависит следующее действие.
  • У каждого факта есть владелец и срок жизни.
  • Trainer — один из примеров этой модели.

Одна модель, разные интерфейсы

ВопросТерминалНастольное приложениеReact
Где память?Переменные процессаОткрытый документState компонента
Что меняет её?КомандаВвод или кнопкаСобытие
Что видит человек?Строка статусаОкноRender
Когда исчезает?Завершение процессаЗакрытие документаРазмонтирование владельца

Терминал. Переменные процесса меняет команда; программа печатает новый статус; память исчезает с завершением процесса.

Настольное приложение. Открытый документ меняют ввод и кнопки; результат виден в окне; память исчезает при закрытии документа.

React. State компонента меняет событие; результат показывает render; память исчезает при размонтировании владельца.

Документ и одностраничное приложение (SPA)

  • Новый документ: новая память JavaScript страницы.
  • Внутренний переход меняет экран без перезапуска приложения.
  • Это вебовый частный случай общего вопроса о сроке жизни памяти.

Где может жить значение

  • Значение в DOM живёт с узлом поля.
  • Локальный state переживает render, но не размонтирование владельца.
  • Controlled field получает value или checked из React.

Действие, состояние, отображение

команда / ввод / ход → новое состояние → новое отображение
  • Терминал печатает новый статус, игра обновляет поле.
  • React передаёт textarea value и radio checked из state.
  • Обработчик переводит событие в обновление состояния.

Общий владелец данных

  • Один документ может питать текст, заголовок и счётчик слов.
  • Stateful-компонент хранит state; stateless показывает props.
  • Общие данные хранит ближайший общий владелец.

Идентичность и позиция

  • Книгу переставили на полку, но её идентичность не изменилась.
  • Индекс — позиция карточки на экране.
  • Task.id связывает Answer с конкретным заданием.

Как меняется состояние

  • Один Task.id — один актуальный Answer.
  • Новая коллекция описывает результат действия.
  • Старую коллекцию не меняем на месте.

Исходные и вычисляемые данные

  • В корзине хранят товары и количества, а сумма вычисляется.
  • В попытке хранятся ответы и режим; прогресс вычисляется.
  • Пробелы в short-text не считаются ответом: trim().

Владелец и срок жизни

  • Процесс, документ, компонент и база данных живут разное время.
  • URL и browser storage переживают текущий документ.
  • В A3 попытка живёт в памяти React до перезагрузки.

Навигация и данные

  • Переход меняет текущую карточку, но не обязан менять ответ.
  • Как вкладка редактора не стирает текст другой вкладки.
  • Карточка читает ответ общей попытки по Task.id.

Режим завершённой попытки

  • Как документ «только чтение» или заказ «оформлен».
  • Пропуски дают предупреждение; отмена сохраняет попытку открытой.
  • submitted закрывает редактирование, но не меняет ответы.

A3: локальная попытка

  • Radio, textarea, навигация, ответы и вычисляемый прогресс.
  • При пропусках — подтверждение; при полном заполнении — прямое завершение.
  • Без API, серверной оценки, fetch и localStorage.
